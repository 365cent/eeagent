# 验收执行记录模板

本文件是空白模板，不是执行记录或验收证据。复制后**每个 AT、每个实际执行目标/样本批次各建一份记录**；不要覆盖模板。复制出的记录初始状态必须为“未运行”，其他字段保持空白，只有真实执行后才能填写结果和证据。AT 的来源、判定条文和任务映射以[需求追溯表](REQUIREMENTS-TRACEABILITY.md)为准。

建议将已填写记录保存至 `docs/acceptance-records/<release-or-build>/`，文件名使用 `<AT-ID>-<target>-<run-id>.md`。若证据保存在受控的外部证据库，记录稳定链接和访问位置；不得将秘密、凭据或未获准的个人/客户资料写入仓库。

## 记录和结果规则

- “未运行”表示尚未执行；“受阻”表示已尝试启动，但环境、权限、输入或依赖阻止检查完成；“失败”表示已执行且观察结果不满足判定条文；“通过”只用于判定条件全部满足并有可复核证据的执行。
- 不要把计划命令、预期输出、空页面、非空 JSON、模拟服务或按钮状态记为通过。一次记录只描述其注明的版本、样本、环境和实际步骤；不同平台、版本或样本批次分别记录。
- **macOS**：依照根目录 [README.md](../README.md) 记录实际工具版本和数据库目标。针对 `eea_test` 的隔离自动化及前端构建/本机走查只能证明所记录的 Mac 组件范围；不能代表 Linux 服务行为、Windows GUI/Edge/Chrome 采集或真实业务准确率。
- **Windows**：客户端 GUI、安装/升级、队列恢复及 Edge/Chrome 真浏览器采集须在对应 Windows 版本和浏览器上记录。Mac 可移植 Go 检查不能替代这些验收。
- **Linux**：生产候选验收须记录实际 Linux 预生产目标、服务/迁移/身份/TLS/worker/恢复等步骤。Mac 上的 PostgreSQL、Next 构建或 API 冒烟不能记作 Linux 验收。
- **真实业务验收**：记录获准的来源身份、样本清单/版本和人工判定依据。合成夹具可验证技术行为，但不能替代真实来源准确率、跨主体共识或业务签收；不得以人工粘贴冒充自动采集成功。
- 缺少必要输入或平台时保持“未运行”；若已尝试但被阻断，记“受阻”并关联解除条件/责任人。证据链接应可由复核人访问，并避免暴露凭据或未授权资料。
