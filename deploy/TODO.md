# Linux 内网生产实施清单

更新：2026-11-05。本目录承载部署实施及后续实际配置；已有 API/Next 前台服务单元模板与配置说明，但**尚未交付经 Linux 验证的安装脚本或上线产物**。项目顺序见 [总清单](../TODO.md)，业务验收见 [需求追溯表](../docs/REQUIREMENTS-TRACEABILITY.md)。模板入口：[部署说明](README.md)。

默认单主机方案：Linux、PostgreSQL、API/Next/worker 的 systemd 服务、Nginx TLS 同源入口、独立持久对象目录。生产服务前台运行；数据库和对象目录不得放在版本发布目录内。Worker 命令与模板已补，仍待 Linux 生命周期验证。

## OPS-03 TLS、可信身份与权限

- [ ] P0 · 未开始 · 身份/角色契约与演示配置可先设计；实际域名、证书和用户映射依赖 DOC-02。BE-03、CC-03、FE-12 是共同实现/验收方，不是前置依赖。
- 来源：REQ-RULE-02、REQ-AGT-04/05；WBS 1.2.5/1.6。
- 设单一 HTTPS 入口：页面及 /api/v1 同源转发，TLS 使用企业可信 CA；API/数据库/worker 仅内部监听。
- 反向代理完成可部署的认证并写入受信 subject/role；剥离客户端同名头，应用仅接受受控代理来源。具体认证方式和会话撤销方式需在环境登记。
- 研究者执行采集与自身任务；方法论/词表管理员执行分类/归集复核和业务确认；运维执行运行维护。默认拒绝未知角色；IP 访问记录不授予权限。
- 对用户签发可撤销、带过期时间/作用域的 capture 凭据，只允许上传与其任务查询；服务端保存安全校验材料，客户端使用 Windows 凭据存储。
- CORS 限定实际部署来源；按认证方式落实 CSRF 防护，禁止公开信任任意私网来源或请求体中的操作者身份。
- 验收：未登录/伪造头/错误角色/过期 token/跨用户任务均被拒绝；真实用户操作写入准确身份，不因重启丢失映射。

## OPS-04 服务、任务与可观测性

- [ ] P0 · 部分实现（未在 Linux 验证）· 本目录已有 `eea-api.service` 与 `eea-web.service`；其余依赖 OPS-01/02、BE-01/03/12/14。
- 来源：WBS 1.6/1.7；持久证据、人工审计和会话要求。
- API/Next/worker systemd 模板首版已交付，证据见[交付记录](../docs/DELIVERY-RECORD.md#ops-04--service-unit-templates)；路径、权限、生命周期及代理行为仍须按实际 Linux 主机验证。
- [ ] 在目标 Linux 验证 API/Next/worker 服务启动、停止、重启、健康路由与反向代理。
- 配置依赖、受限权限、工作目录、环境文件、优雅停止、重启策略和资源限制；迁移使用受控发布步骤，不由每个 worker 抢跑。
- API 原始文件写入成功后建立持久任务，worker 处理超时/重试/租约/取消；进程重启不能丢队列或重复应用业务改动。
- Nginx 上传限制和服务限制一致，SSE 关闭响应缓冲并设置合理超时；静态资源、归档下载和大文档任务分别验证。
- 分离存活/就绪检查，检查 DB 与对象目录；模型网关不可用显示降级能力，不能把数据存储故障报告为健康。
- 记录请求/任务关联 ID、错误、延时、队列积压、磁盘、失败率；日志轮转，默认不记录正文、凭据或完整对话。
- 验收：服务重启、机器重启、worker 中断后任务可恢复；SSE 可用；失败有可定位日志与明确状态。

## OPS-05 备份、恢复与回退基础

- [ ] P0 · 未开始 · 依赖 OPS-01/04、BE-16、DOC-02 恢复目标。
- 来源：证据留存、版本历史；WBS 1.6.2、1.7.2。
- 定义数据库、原始 HTML/文件、图块、报告、配置和所需秘密的备份边界；文件可追溯至数据库对象键。
- 在受控写入窗口或一致性机制下备份数据库与对象目录，生成清单/校验和；备份加密保存在独立位置并限制读取权限。
- 形成保留周期和定时执行/失败告警；RPO/RTO 由业务与运维确定并记录，未定值时不可声称生产恢复能力已验收。
- 在另一数据目录/隔离数据库实测恢复，核对信号数、对象可读、标准空白、历史评分和会话权限。
- 说明应用包回退与数据库回退不同：兼容迁移可回旧包；不兼容变更需维护窗口恢复备份并登记其间数据处理。
- 验收：恢复耗时和可恢复时间点达约定目标；演练不覆盖真实生产库，备份不是仅“文件存在”。
